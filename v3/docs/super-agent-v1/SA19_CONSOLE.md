# SA19 来源与任务控制台

SA19 是原账户、Source、策略、预算和任务的组合界面。独立验收前保持 IN_PROGRESS；不启动 SA20。真实平台、付费、编码、通知外发、发布与长期运行均未因本卡放行，固定 H12 真实 Agent/MVP FAIL 保留。

登录既有账户后，从首页“来源与任务”进入 `/source-console`，补丁仍到 `/source-reviews` 完整审查。页面只展示当前服务项目。所有管理操作要求当前 Owner cookie；写操作沿用 Origin/CSRF。浏览器 bearer、来源正文、显示名都不能替代 Owner。

第一次配置按以下顺序进行：

1. 在“来源设置”添加一个 GitHub App 安装及本项目仓库，或一个飞书机器人及授权研发群。填写完整数字 ID 或大小写敏感 opaque ID，选择允许的用户、事件、群和跟进话题；GitHub 用户 ID 不使用登录名代替。飞书默认只收 @ 与所选话题，选择全群或历史需要额外真实平台权限。
2. 展开安全凭据输入，填写对应平台的完整凭据及有效期；留空会保留既有值，替换需全部字段。保存尝试结束清空输入，不回显原值。页面验证失败且尚未提交时，请自行清空或修正输入。不要在聊天、URL、普通配置或仓库中填写真实密钥。
3. 到“规则与用户”核对用户和事件，保持 Shadow，预览并保存规则，再“确认网关接收与影子观察”。接收、正文保留、模型输入、执行和通知各自授权。预览只作确定性判断，不运行语义评估，不创建任务。受控模型或未调用模型的候选也不会被显示为真实语义成功。
4. 在“预算与投递”填写组织标识，首次可同时创建组织和项目共享上限；已有组织取消首次创建选项。组织和项目使用原共享账本，既有组织额度不会静默改写。部分保存失败时，已提交的组织事实保留；刷新后核对版本再保存。默认金额、Token、Worker 槽位为零，只设置有界候选和来源速率。非零额度需明确价格，配置上限不创造付款许可。
5. 用户身份仅从已部署受信接收器验证的当前平台事件中选择。核对安装和完整用户 ID 后绑定角色或 Owner；绑定本身会推进身份版本，需要新可信事件才能再次产生当前 proof。机器人只有上下文角色。任务控制者还需要原有具体任务成员授权，角色本身不授予任意任务控制权。
6. 查看来源的“连接”与“消息权限”两项。在线并不代表有消息读取权限；无 Runtime、无诊断或诊断过期显示未知。新鲜的 insufficient/revoked 负面诊断保留。来源改版后旧正面诊断不能继承。权限不足需在平台补齐并重新确认，由已部署受信服务检查。

保存配置不会启动平台长连接、Webhook、定时任务、模型、Worker、Dispatcher 或发布。服务端 Runtime 的组合与激活继续由受信部署层承担；SA19 不伪造平台安装和 live activation。该界面完成本卡的来源范围、凭据、规则和观察配额设置，生产部署仍属后续卡。首页原模型设置继续使用既有安全输入入口。

“观察与任务”展示原 Fast Path 决定、语义状态、建议及依据。NOT_RUN 明确表示没有模型调用；模拟提案即使已有 would_ignore/create/attach，也不冒充模型执行。原 Ticket/Thread/Run、来源授权和关联、Assignment、Job、费用与未知预占均来自原业务表，页面不读取聊天原文、代码、私钥、模型响应或 Job 日志。列表有界：最近50项决定/任务/动作，最多100项身份；超过上限明确提示，概况数量按可见记录计算。

自动修复选项在当前 Worker 能力门下不可选，服务端同样拒绝 auto_repair、编辑和测试能力。自动调查仍需当前的精确仓库/base SHA/路径、身份、策略、预算和执行许可。页面保存不会启动任务。已有复杂策略的 admission、native_threads、通知 quiet_hours 等限制保留；本页按首版单仓单群编辑，复杂跨来源授权仍使用原精确管理接口。

停止与撤权的影响不同：

- 停用全部来源：以当前 snapshot hash 作 CAS，原 Engine 同一事务撤销现有策略、停用原平台配置/Ingress、擦除当前凭据密文，并取消来源关联原 Run。中途失败整体回滚，不增加平行全局状态。
- 撤销某来源：检查当前 Source revision，组合原撤权和 fencing。旧网页、旧凭据和旧规则不能恢复已撤权正文或执行权。保留必要无正文审计及历史费用。
- 停止任务：检查页面所见 execution_epoch 后调用原 Engine.cancel。已开始的请求无法被取消事实抹除；后台 Job、Assignment 和未知回执继续收尾，不伪称外部操作已撤回。
- 收起页面或关闭浏览器：只停止查看；不发送 cancel/unload 请求，不改变原任务状态。常驻宿主关机后的执行能力属于 SA20，不能由此页面推断。

投递成功、已验证补丁、待审、unknown 是不同事实。unknown 必须只读核对，不自动重发，也不重跑任务。通知许可独立，Draft PR 仍需完整 Diff/tree/精确 hash 的原审查流程；本页无发送测试、批准任意补丁、merge 或部署按钮。

凭据存储复用原 Engine 持锁 PG 连接。0052 仅有加密凭据当前值及无正文元数据审计两表；不产生第二个任务状态机。服务端密钥固定在 `artifact_root` 父目录的 `source-console-credentials/key.bin`，目录0700、文件0600，拒绝符号链接/硬链接/不安全权限。文件/加解密在业务事务外，释放结果或提交前重查当前 Owner、Source、credential/config revisions；密文绑定项目、安装、scope 和凭据版本。HTTP 无解密/导出入口，备份必须同时保护 PG 与密钥；删除或丢失密钥不能当作已恢复凭据。

共享范围依据 Harness `8d19308a585e80885fc4f0bfeec4853395236ab8` 第45节：0052、原 Engine/API/agent.html 三文件精确补丁、12个 Owner API 与3个页面/资源接口。SQL/补丁哈希见 `sa19-proposal/ownership-confirmed.json`。不改历史迁移、财务算法或 Harness 活动树。应用仓库有49份正式迁移；本机 SA 主库仍44份，不能直接向其安装0052冒充隔离验收。

本卡完整注册为 `make verify TASK=SAV1-19`；准备、HTTP、浏览器、边界与交付另有分范围目标。默认指向的数据库必须是明确隔离测试PG。交付证据按候选提交、官方指纹、不可变源码归档和 JUnit 绑定；修复后只执行原失败 case/target，已通过项按其版本保留，不宣称最后源码单轮全量通过。静态检查同样列明覆盖版本。具体成绩与未测项见工程交付报告。
