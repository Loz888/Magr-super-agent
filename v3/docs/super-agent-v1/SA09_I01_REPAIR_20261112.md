## 根因与修复边界

原候选 `93e9a9d9a64bdd19889071ebf3ee33d3e46bb482`，源码指纹 `684fe90a43065e642860ca3b99fbc932406951e92b3bd41392eb590e386436ce`，在 RouterBudget 预占事务提交后直接进入模型调用。此时 Source 策略撤销或移除 context_provider 可先通过原 Engine 正式接口提交，后续 POST 却仍使用先前组装的正文。模型冻结请求和根许可的校验没有重新读取当前 Source 授权，因而不能关闭这一窗口。三组原失败分别覆盖预占后撤权、真实线程竞态，以及预占持久提交至模型入口的精确边界，均属于同一 P1：SA09-I01。

修复仅改私有 `source_eval.py` 和 `source_eval_model.py` 的生产逻辑。Provider 通过模块级 ContextVar 为本次调用绑定 `guard_source_send`；真实 SourceEvalModel 完成 `request_body` 后、进入网络异常处理之前进入该 guard。guard 持原 Engine 互斥锁，以原连接的短事务重新执行 `_checked`，重建请求并核对请求 SHA、实际 body digest、当前签署的上下文/输出上限、当前 call 的 reserved 状态及根许可。事务提交后继续持锁，直至 `client.stream.__enter__` 返回响应头；网络发送时 PG 已处于 IDLE。先提交的撤权因此阻止旧正文 POST，排在栅栏之后的撤权须等实际发送进入后才能提交。

模型拒绝 HTTP 客户端 request hooks，并显式传 `auth=None`，防止继承的请求钩子或认证回调在同一线程重入原 Engine，绕过 RLock 的线程间排序。收到响应头后立即释放锁，允许流读取期间正常撤权。该约束适用于受信 runtime 注入的真实 SourceEvalModel；自定义模型或 transport 仍属于受信运行时能力，模型 JSON 不能提供 guard 或授权。

发送前 guard 拒绝会传播固定 DomainError；Provider 使用原 `RouterBudget.settle(call_id, None)` 保留 unknown 和原预占，不退款、不自动重发。请求确已发出后，合法已知 usage 的真实费用仍与无正文 sanitized 结果在原 Engine 同一外层事务结算；后续权限变化不能回滚实际费用，业务接受阶段仍重新校验快照。未知 usage 保留原账本 unknown；canonical 输入调用关联与原 Engine.recover 继续阻止通过新批次、成员或配置 revision 重发。没有新增费用账本、业务写者、迁移，也没有修改共享 Engine/API/Routing/预算代码、原三处财务结算 AST 或 Harness。
