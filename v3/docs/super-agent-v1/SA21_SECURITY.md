# SA21 隐私、安全与灾难恢复

SA20-I01 的独立原失败项 1 PASS 已核对并获用户接受；见[关闭记录](accept/SAV1-20/independent-closure-20261115.json)。SA21 当前 IN_PROGRESS；本卡首次检查尚未运行，SA22 未启动。真实平台、付费、外发、发布和长期门保持 NOT_RUN，固定 H12 真实 Agent/MVP FAIL 保留。

本卡验证已有权威边界之间的组合，加入显式 Owner 保留状态检查器 `SourceSecurity(engine).inspect(cookie)`。检查器只使用调用方原 Engine 的持锁连接及短事务；不另开业务连接、不读取正文/密钥/CAS、不裁决权限或宣称安全门通过。每次最多列出当前项目 32 个来源，超过时标为 partial；过期密文、待清理 metadata 和 unavailable 密文分别计数。实际清理仍使用原 `SourceIngress.purge`，没有新的自动删除任务、表、API 或激活开关。

本轮不修改共享 Engine/API/schema/预算、不新增迁移或预占 0054，不操作 Harness 活动树。新的注册入口仅纳入本卡首次组合检查；历史已通过测试不重新列入。发现问题后仅重跑失败目标，保留原始失败及按版本绑定的通过证据。

## 数据生命周期和处置

| 阶段 | 保留与权限 | 删除/撤权及恢复处置 |
| --- | --- | --- |
| 外部原始事件 | 受信验签、安装/租户/作者/会话范围；外部文本不授予权限 | 拒收不存正文；只保留有界最小凭证/水位/歧义事实 |
| 原入站正文 | Source 独立 AEAD 密文、当前 Receive/身份/版本、正文与 metadata 的独立期限 | 原事务删除密文并失效旧输入；显式 purge 到期内容，不删除去重/审计水位 |
| 模型上下文与审计 | 获准内容仅在最终当前权限检查后进入明确受控模型；审计保留引用/摘要哈希和枚举 | 输入撤权后不可从旧批次再次发送；未知费用保留预占，结构无效不建任务 |
| Recall、Memory、派生 CAS/导出 | 当前调用方、逐跳关系及全部来源依赖；Memory 文本不授予执行权 | Source 失效同时拒绝原文、旧游标、Memory 和派生产物读取；内容与最小状态分开 |
| 待发与 unknown | 原 Action/Approval/Outbox；通知只含固定最小模板与任务 ID | 待发同事务取消；已发 unknown 保留真实账本，不变成未发送、不自动重试 |
| 加密备份 | 离线一致性 PG/CAS/三种密钥，独立包外备份密钥，操作者控制备份保留期 | 旧包不因新撤权自行改变；新空库/目录恢复后保持 hold，先重放最新删除/撤权、对账、轮换，再由操作者决定是否激活 |

备份不能充当新鲜授权。没有最新删除/撤权记录，或有未知外部写/费用、未核对 Job/lease 时保持 hold；不能仅凭包哈希有效移除 hold。本卡在显式离线维护中重放受信删除事件/原策略撤销命令，再检查原文、派生 CAS 与 Memory 同时失效；测试不移除 hold、不启动服务。受信离线操作者可以读取备份及旧密钥，这与对外业务接口的当前 ACL 边界分别报告。

不可变费用/Delivery/tombstone/最小审计保留，不通过删除账本退款或制造重复执行。已发送的外部消息不能由本地删除假装撤回；平台删除能力、实际备份介质销毁/密钥轮换、物理磁盘及多节点灾难未实测时明确 NOT_RUN。普通日志、导出与证据不得包含真实凭据或用户正文。本轮所有正文、模型响应、来源签名和通知目的地均为合成数据。

## 冻结的受控检查范围

首次注册 `make verify TASK=SAV1-21`，范围 25 项新检查，细分如下。原 13/55/88 项不重跑；此前 Source/权限/配额/Worker 等工程证据继续按原候选保留，不声称本卡单轮覆盖所有旧用例。

| 检查组 | 本轮新检查 | 事实边界 |
| --- | --- | --- |
| 接收到 Recall/Memory/CAS | delete/edit/identity/policy 四种失效；新请求与首屏旧游标拒绝 | 原 Source Gateway/身份/策略操作完成提交，而非直接设置预期状态 |
| 接收到通知 | 三种失效 × pending/unknown 六例 | 原 Outbox 待发取消，已发生 unknown 不重发、不丢账 |
| 来源与保留 | 三种假签名/跨会话/未绑定作者；真实 TTL/purge；只读检查器 | 不存拒收正文，保留最小事实，检查不解密 |
| 模型与输入审计 | 两种流丢失/结构无效后撤权 | 真实 PG 预占/结算，HTTP MockTransport 明确零真实外发；重复请求不重新发送 |
| 写者、调度与项目 | 竞争领取并取消旧 Worker、第二写者拒绝、另一合法项目隔离 | 原 Engine 锁、两个并发提交方与真实 PG 事实 |
| PostgreSQL 故障 | 提交前、提交后两个真实服务 SIGKILL/启动 | 独占带随机 ownership label 的 PG 容器，原未提交不 ACK，已提交幂等复用 |
| 旧备份与存储故障 | 两种旧备份隐私重放；一次 DB 已恢复后的真实 OS EFBIG | 实际 pg_dump/restore、CAS/密钥、启动 hold 和 unknown 不重发 |

故障仅针对本轮唯一创建的隔离容器、临时数据库和目录；主库 55435 不迁移、不重启。Docker 镜像固定摘要且 `--pull=never`，清理前核对完整容器 ID/名称/owner label。存储故障使用独立子进程的内核文件大小限制，实际原恢复代码写入触发 EFBIG；不把它写成整盘 ENOSPC、主机断电或云存储丢失实测。

本轮失败、命令、退出码、JUnit、逐例源码归档和清理记录放 `evidence/super-agent-v1/SAV1-21/`。每次先固定提交并核对归档源码指纹，修复期间不重跑已经通过的范围；分版本结果与独立验收分开。整卡在独立验收和用户放行前保持 IN_PROGRESS，SA22 不自动启动。
