## 缺陷与修改

[原独立报告](../../evidence/super-agent-v1/SAV1-18/independent-review-20261115T080306Z-407dcbff/REPORT.md)、原失败日志及实际 Git 对象证明缺陷属实：发布适配器先读取远端 head/base，再由 `io_guard` 最后采集 H03 工作区；采集期间远端已推进，采集后的 SQL 权限检查无法发现它，commit 已实际写入，随后阻止 Draft PR 不能撤销这次写入。

修复只改 SA 私有 `source_review_transport.py` 和 `source_reviews.py`：将原有远端判定提取为回调，在 `io_guard` 内工作区采集/完整 Bundle 比较完成后调用，并保留远端读取回调之后的最终 SQL 权限复核。所有写步骤统一按以下顺序执行：

1. 原 Engine 事务提交当前发布步骤及请求 hash 预占。
2. 在事务外采集实际 H03 工作区，与获批 Bundle 完整比较。
3. 在事务外读取当前远端 base/head；Draft 步骤继续核对完整 tree/父提交/blob。
4. 最后在原 Engine 同一持锁连接、RLock 和短事务内复核 Source、Owner、lease、epoch、async/input revision、审批及原目标。
5. SQL 事务结束后，才调用当前步骤的物理写端口并记录原回执。

这样既能阻止最后采集期间已发生的远端变化，也不会将远端回调挪到最终权限读取之后。未知结果仍沿用原只读对账路径，不重发、不恢复 ready、不续发。原步骤预占、目标/完整对象判定与撤权守卫没有删除。

没有改 Engine/API、共享读写端口、路由、预算或迁移，无需新增共享范围。0050/0051和所有48份迁移保持原字节；操作说明与对应产物哈希已同步。
