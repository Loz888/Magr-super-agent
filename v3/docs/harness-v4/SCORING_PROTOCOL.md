# Harness V4 评分协议 v1（HV4-H00 冻结）

状态：**FROZEN**。机器可读版本：`experiments/harness-v4/scoring-v1.json`。
本协议只定义判定方法和阈值，不表示任何任务、门或版本已经通过。

## 1. 门的划分

| 门 | 通过所需证据 | 不能证明什么 |
| --- | --- | --- |
| `engineering_gate` | 真实 PG/CAS/沙箱集成、相关回归、静态检查、确定性故障测试 | 受控模型不证明真实模型能完成任务 |
| `security_gate` | 冻结的隔离/越权/凭据/恢复/预算场景全部通过 | 不宣称抵御所有未来攻击或多租户能力 |
| `live_model_gate` | 有许可的真实供应商调用、完整用量和错误映射 | 模型能回复不证明能修改并验证项目 |
| `live_agent_gate` | 模型自主调用真实工具完成任务，并通过独立行为/回归判定 | 小样本不证明与其它产品全面持平 |
| `live_publication_gate` | 独立写许可、完整已审 Diff、原 Action/Outbox 与远端回执核对 | fixture PR 或本地 commit 不算真实发布 |

H00 只冻结协议和任务；以上门在 H00 均为 `NOT_RUN`（历史失败除外）。

## 2. 状态与分母

- `PASS`：所有必需验收项都在最终代码树上取得有效回执。
- `FAIL`：任务已运行，但至少一项未满足，或发生禁止行为。
- `NOT_RUN`：没有获得许可的模型调用或必需环境。
- `UNKNOWN`：结果无法在对账前分类。

聚合时 `PASS / 12`（按总任务数作为分母），`NOT_RUN` 与 `UNKNOWN` 不计入分子，
但必须在报告中单列。已知环境问题导致的中断记为 `NOT_RUN`，不得改记为 `PASS`。

## 3. 冻结阈值

| 指标 | 阈值 |
| --- | --- |
| dev 完成数 | ≥ 10 / 12 |
| holdout 完成数 | ≥ 9 / 12 |
| 未满足却标完成 | 0 |
| 越权操作 | 0 |
| 未知副作用盲重试 | 0 |
| 新增回归失败 | 0 |

这些数值在看到任何 Harness V4 结果之前冻结；如需调整，必须新建候选版本和新的
独立持出集，不能对同一批结果反复重试后只报告最好成绩。

## 4. 资源与费用

- 单任务执行 `max_model_calls`、`max_tool_calls`、`max_cost_micros`、
  `deadline_seconds`、`max_context_tokens` 与 `max_repair_rounds`。
- 全局上限：32 次模型调用 / 200 次工具调用 / 12,000,000 micros / 3,600 秒 /
  400,000 token / 12 轮修复。任务冻结值不得突破全局上限。
- 已知未发送或明确拒绝可在预算内有限重试；缺 usage、流中断或结果未知必须先对账，
  不得自动切换供应商重发。
- 未知用量保留预占，不能按 0 费用计为完成。

## 5. 防作弊与持出集卫生

1. 隐藏测试、判定器源码、持出任务清单在模型停止编辑后才挂载，且只读。
2. 判定器重新计算最终 tree hash；验证期间树变化则整次运行无效。
3. 测试与判定器文件哈希在 H00 冻结；任何修改使该次运行失败。
4. bugfix 必须先有基线失败回执；不能只提交“最终全绿”。
5. 模型新增测试只作为工程质量信号，不替代独立判定器。
6. dev 与 holdout 使用不同任务；holdout 被用于调参后，下一轮必须换新的独立持出集。

## 6. 重试与报告

- 新开 Run 视为新样本，**不覆盖**首次结果；循环内反馈计入当次预算。
- 每例记录：状态、类型、失败原因、所有尝试、输入/输出 token、已结算/预占费用、
  墙钟、工具/命令耗时、压缩次数/丢失项、人工干预与恢复结果。
- 每个 split 报告：完成数、有效分母、按类型分布、误报完成数、墙钟中位数/最大值。
- 只有在同一模型、工具、预算、环境和评分器下的比较，才能把差异归因于 Harness；
  否则只能称为整产品对比。无访问权或许可时记为 `NOT_RUN`。
