# 如何理解 Super-Agent 的实验

来源接入、任务关联、执行、验证、送达和发布回答不同问题。每份实验绑定自身的源码、样本与验证类型，不能拼接成一次完整端到端成功。[当前状态](CURRENT_STATUS.md)

## 已有任务的后续消息为什么还要路由？

2026-11-06 的 [E/F v2 报告](experiments/coordination-v2/README.md)使用执行源码 `ff6353d`，在固定合成来源负载上做两次重复、Worker 来源缓存冷热条件与两种方案，共 8 次真实模型运行。E 的 Router 调用 32 次，F 为 12 次：减少的 20 次中，16 次来自订阅直达，4 次来自批处理。即 **Router 调用减少 62.5%**，并非所有模型调用或总费用减少 62.5%。

每臂路由 36/36、负例 12/12；正常任务 E 为 7/8、F 为 8/8。E 的一项完整行引用被独立 Oracle 判 FAIL，原 Verifier 接受的情况保留。实验为小样本、开发者可见、非盲测，一个事件只有一个合法候选；真实 LangGraph Worker 与模型调用不能把合成来源标签变成真实 Webhook 投递。结果说明在这组条件下订阅接续节省路由，不能推断普遍模型协调推理更强，也不是 SA22 当前版本全链路成绩。[原报告与条件](experiments/coordination-v2/README.md)

## 哪些结论需要继续分开？

- 受控工程检查、真实平台接收及反馈、正式独立评分各有不同证据。2026-11-18 的 L03 A04 独立 1 PASS 只覆盖定向复验，原 FAIL 和待补连续场景保留。[并行记录](super-agent-v1/SA22_PARALLEL_20261118.md)
- 路由开发输入、标签冻结及正式评分不等同；当时仅有 4 项开发集工程检查，正式评分未完成。[并行记录](super-agent-v1/SA22_PARALLEL_20261118.md)
- 历史 P0 与 V3.5 的实验、真实 Draft PR 或受控演示各有自己的对象及门禁，不自动成为 SA22 的成绩。[P0 历史交付](repairs/P0-20261107/README.md) · [V3.5 历史演示](v35/DEMO.md)
- 受控运行窗口的已观察时长、真实渠道 72 小时、5 个工作日及主机关机验证不能相互替代。[SA22 进展](super-agent-v1/SA22_PROGRESS_20261118.md)
